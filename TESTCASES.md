# Тест-кейсы API qa-internship

**Объект тестирования:** микросервис объявлений, хост https://qa-internship.avito.com
**Источник требований:** условие задания и Postman-коллекция `postman_collection.json`

## Общие положения

**Тестовые данные.** Стенд общий, поэтому в каждом кейсе используются **уникальные** данные:
- `username` вида `qa_<uuid>`;
- `password` вида `Pass_<uuid>`;
- `name` объявления вида `qa-item-<uuid>`.

На данные других кандидатов кейсы не опираются.

**Валидное объявление (далее «валидный payload»):**
```json
{
  "sellerID": <id текущего пользователя>,
  "name": "qa-item-<uuid>",
  "price": 9900,
  "statistics": { "likes": 21, "viewCount": 11, "contacts": 43 }
}
```

**Общие предусловия и постусловия:**

| Код | Описание |
|---|---|
| **P-USER** | Зарегистрирован новый пользователь (`POST /api/1/register` → 201). Получен Bearer-токен (`POST /api/1/autorize` → 200). Все защищённые запросы отправляются с заголовком `Authorization: Bearer <accessToken>`. |
| **P-ITEM** | Выполнено **P-USER**. Пользователь создал объявление с валидным payload, его UUID извлечён из поля `status` ответа. |
| **Постусловие** | Все объявления, созданные в кейсе, удаляются через `DELETE /api/2/item/{id}`. |

**Применённые техники тест-дизайна:**
- **КЭ** — классы эквивалентности;
- **ГЗ** — граничные значения;
- **ТР** — таблица решений (матрица «ручка × вариант авторизации»);
- **СП** — диаграмма состояний и переходов (объявление: создано → удалено);
- **ПО** — предугадывание ошибок.

**Приоритет:** High / Medium / Low.
**Автоматизация:** все кейсы автоматизированы в `test_api.py`; ID кейса совпадает с заголовком `@allure.title`.

## 3. Доступ к защищённым ручкам (таблица решений)

**TC-ACC-01.** Все защищённые ручки отклоняют запрос без валидного Bearer-токена.

- **Предусловия:** **P-ITEM**.
- **Шаги:** для каждой пары «ручка × вариант заголовков» из таблицы ниже отправить запрос.
- **Ожидаемый результат:** для каждой комбинации возвращается **401 Unauthorized**; данные не создаются и не удаляются.
- **Техника / приоритет:** ТР, ПО / High.
- **Автотест:** `test_api.py::test_protected_endpoints_require_auth` (18 комбинаций).

| Ручка ↓ / Заголовки → | Без `Authorization` | `Authorization: Bearer invalid.jwt.token` | Подмена через `X-UserId: 1` |
|---|---|---|---|
| `POST /api/1/item` | 401 | 401 | 401 |
| `GET /api/1/item/{id}` | 401 | 401 | 401 |
| `GET /api/1/{sellerID}/item` | 401 | 401 | 401 |
| `GET /api/1/statistic/{id}` | 401 | 401 | 401 |
| `GET /api/2/statistic/{id}` | 401 | 401 | 401 |
| `DELETE /api/2/item/{id}` | 401 | 401 | 401 |

- **Предусловия:** нет. **Приоритет:** High.

## Вне автоматизации

Осознанно не включены в регулярный прогон `pytest`:
- **полноценное нагрузочное и стресс-тестирование** — стенд общий для всех кандидатов, поэтому выполнялся только короткий щадящий smoke-замер (TC-NF-01) и проверка гонки на 5 потоках (TC-NF-02);
- **истечение срока жизни JWT (TTL)** — время жизни токена не регламентировано в документации.
